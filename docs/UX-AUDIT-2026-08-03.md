**Scope:** the kernel only — `vibe start/init/token/who/status/dm/inbox/reply/help/bye` and pending-message presentation.
**Method:** every kernel state rendered against synthetic fixtures (`scripts/render-states.mjs all`), before and after. ## Beat: send / reply — "claim success only after the exact operation succeeds"

**The worst finding in the pass.** `store.sendMessage` returned `null` when a transport error was thrown; `dm` and `reply` both checked `result && result.error`, which reads null as success.

| | before | after |
|---|---|---|
| dm, network down | `Sent to **@rune**` | `That didn't send — nothing was delivered.` + one retry line |
| reply, network down | `✓ Replied to **@rune**` + `_1 message marked as read_` | same failure shape as dm |

Fixed at the definition: the store now returns a shaped `transport_failed` error (and a bodyless success still returns truthy), and both tools treat any falsy result as failure. Remedy-carrying errors (`auth_expired`, `handle_not_found`, …) show as-is with no stacked second instruction. Failure copy now names `vibe help troubleshooting` — the old hint said `vibe doctor`, an **admin-gated tool a default install doesn't have** (the `vibe_open` drift class).

## Beat: send while they are away — the async model, stated

`Sent to **@rune**` said nothing about the demo's core beat. After: when the recipient has no recent heartbeat, one quiet line — `_@rune is away — it'll be waiting on their next turn._` Presence lookup is best-effort; a real send never turns into noise if presence is unreachable.

## Beat: see a trusted collaborator — people, agents, sessions distinguishable

The store's normalized field is `isAgent`; `who.js` read `u.is_agent` — a field that never exists. Three consequences, all live in production:

1. The 🤖 badge was dead code: **@atlas rendered identically to a person.**
2. The `(op: @handle)` operator tag never rendered (the store also dropped `operator` in mapping — now mapped).
3. `_shared.pickDormantTarget` filtered agents with the same dead field, so the first-DM activation nudge told a newcomer **"@atlas is around right now — dm @atlas"**: the "message a real person" feature pointed at the agent.

After: badge and operator render (active and away sections), structured mirror agrees with the board, nudge picks the human. One canonical name (`isAgent`), pinned by tests.

## Beat: see a trusted collaborator — "green means only a recent confirmed heartbeat"

The server files anyone seen in the last **30 minutes** under `status: "active"`. The board painted the whole bucket green: `🟢 @mira … _25m ago_` — green next to the timestamp disproving it. Heartbeats arrive every 30s from a live session (5m from the slowest source; the server's own source TTL is 10m).

After: 🟢 requires a heartbeat within 10 minutes; staler rows render as away regardless of the server bucket, in both the board and the structured mirror. Also dropped the `active` heat label — a word that repeated the glyph, and only on some rows, reading as a difference that wasn't one.

## Beat: sign in — init / token / status

- `vibe status` with no mood was a **raw TypeError** (`mood.toLowerCase`). Now copy: the command and its options.
- `vibe token` guidance said `vibe init @yourhandle` — a syntax that doesn't exist (GitHub username becomes the handle). Now matches the real flow; the "🔒 old local keys removed" line renders only when keys were actually removed (it previously showed for users who never had keys).
- `vibe init` (already-signed-in) advertised `vibe logout` — **no such tool is registered**; the sign-off that exists is `vibe bye`. The `vibe email` nudges are now gated behind `VIBE_EXTRAS` (email is culture-layer; with extras off it advertised a command the session doesn't have).
- `requireInit` copy: "⚠️ Not initialized." → what to do and what will happen.

## Beat: clean install → help

- "Join room" → "Start your session" (room language is retired scope).
- dm described as "lands in their live session" → the async truth: now if they're in a session, next turn if not. Same fix in the dm tool description, which also stopped advertising games/tips/artifact cards, and now states **plain text is what's transmitted** (no implied repository context).
- Docs link → `www.slashvibe.dev` (non-www loses POST bodies; one canonical host).
- who-empty no longer suggests greeting **@vibe** — a system account that presence filtering makes invisible, contradicting the private-fabric copy the empty inbox already carries. It now says: dm whoever invited you.
- reply's caught-up state suggested `vibe reply "message" --to @x` — a CLI flag that doesn't exist. Now a plain `vibe dm`.

# Handoff — what this PR deliberately does not touch

**Product-semantics recommendations (platform lane, decide before acting):**

1. **Server `ACTIVE_THRESHOLD = 30` min** (`api/lib/presence-service.js`). This PR gates green client-side; the honest fix is server-side — either a tighter `active` bucket or an explicit `lastHeartbeatAt` contract every surface reads. Changes what every client shows: semantics, not polish.
2. **Kernel `vibe_dm` still executes tips/payloads/artifacts** (USDC tip path included). Copy no longer advertises them, but the code paths are live in the default surface. Recommend gating the params behind `VIBE_EXTRAS` — that changes what the tool does, so it needs a decision, not a polish PR.
3. **Free-text status.** `vibe status` accepts fixed moods only; the one-liner is set at init. If the demo wants `vibe status "migration cleanup"`, that's a new affordance — semantics.

**Buddy lane:** nothing here touches Buddy; continuity UX remains on `buddy/continuity-ux` (`platform-buddy-wt`).
